## Components

### Core
- **Entry Point:** `main.lua`
    - Implements the KOReader `WidgetContainer` interface.
    - Manages plugin lifecycle, navigation state, and dispatcher registration.
- **Menu Builder:** `rssreader_menu.lua`
    - Constructs the UI hierarchy (menus, buttons, lists).
    - Handles page tracking and view logic.

### Data Layer
- **Account Manager:** `rssreader_accounts.lua`
    - Factory for creating client instances for different services.
    - Loads configuration from `rssreader_configuration.lua` (or defaults).
- **Local Store:** `rssreader_local_store.lua`
    - Manages locally defined feeds override/defaults.
- **Feed Fetcher:** `rssreader_feed_fetcher.lua`
    - Generic HTTP client using `socket.http`.
    - Parsers for RSS, Atom, and JSON Feed formats.
    - Logic for sanitizing content and extracting images.

### Integrations
- **NewsBlur:** `rssreader_newsblur.lua`
- **CommaFeed:** `rssreader_commafeed.lua`
- **FreshRSS:** `rssreader_freshrss.lua`
- **Epub Backend:** `rssreader_epubdownloadbackend.lua` (Optional)
    - specific backend for saving stories as EPUBs.

## Data Flow

1. **Initialization:** Plugin loads, reads `rssreader_state.json` to restore previous session.
2. **Navigation:** User browses accounts -> feeds -> stories.
3. **Fetching:**
   - Services request feed data via specific APIs.
   - `FeedFetcher` performs HTTP GET and normalizes response into a common Lua table structure.
4. **Rendering:** `rssreader_menu.lua` transforms data into KOReader `Menu` widgets.
5. **Persistence:** Navigation state (current feed, page, story read status) is saved to `rssreader_state.json` on every major navigation event to support resume.
